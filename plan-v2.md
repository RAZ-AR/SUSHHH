# SUSHHH v2 «капсула» — план исправлений и улучшений

Версия 1.0 · 13.11.2026 · касается `app/v2/` (овальный дизайн, адрес `/v2/`)

---

## Коротко

- **Сейчас v2 — красивый прототип, но не надёжное приложение.** Один сетевой сбой навсегда глушит голос, запись не останавливается при блокировке экрана, звук замолкает в фоне, а записи никуда не уходят — только на этот телефон.
- **Порядок работ:** сначала страховка (проверки в CI), потом ошибки, из-за которых что-то ломается, потом скорость, и только потом — общий эфир на сервере.
- **Каждый этап заканчивается рабочей версией** на `/v2/`, проверенной в браузере и на iPhone.

**Сделано (13.11.2026):** этап 0 (кроме 0.4 — нужен аккаунт GlitchTip или Sentry) и весь этап 1. Проверка типов, линтер и 4 сквозных теста Playwright (`npm run e2e`) теперь смотрят v2 и запускаются в CI.

## Этап 2. Скорость и батарея — 2–3 дня

| # | Что | Почему | Как |
| --- | --- | --- | --- |
| 2.1 | **React → Preact** | v2 весит 296 КБ (95 КБ в сжатом виде), из них ~190 КБ — React ради одного компонента `voice-glow`. Библиотека использует только обычные хуки | Псевдонимы `react` → `preact/compat` в `vite.config.ts`. Скрипт станет примерно втрое меньше; сияние проверить глазами |
| 2.2 | **Голос начинает играть сразу, а не после полной загрузки** | Сейчас файл сначала скачивается и расшифровывается целиком | Играть через `<audio>` → Web Audio, как `Player` в `src/audio.ts`; волну для дорожки рисовать из готовой огибающей (поле `env`, как в v1) |
| 2.3 | **Звук в фоне и на экране блокировки** | Буфер Web Audio на iPhone замолкает при блокировке; у v2 нет управления с экрана блокировки и наушников | Переход на `<audio>` (п. 2.2) + `MediaSession` из `src/pwa.ts` (play/pause/следующий) |
| 2.4 | **Анимация в покое** | Кадр перерисовки идёт 60 раз в секунду всегда: стили `--lv`, `--s`, `--c` и т. д. меняются каждый кадр, плюс три сияния и размытие стекла (`backdrop-filter`) | Писать стили только при изменении; в тишине без касаний дольше 10 с — реже обновлять дыхание |
| 2.5 | **Лишние перерисовки** | `render()` каждый раз пересобирает дерево дока (`paintDock` без проверки, что изменилось) и HTML кнопок | Перерисовывать док и кнопки только при смене раздела, состояния или счётчика |
| 2.6 | **v2 без сети не открывается вовсе** | Страница v2 исключена из кэша service worker | Для `/v2/` — «сначала сеть, без сети из кэша» (`NetworkFirst`): свежая версия при сети и рабочая без неё |
| 2.7 | **Лишнее в офлайн-кэше** | При установке скачивается 2,4 МБ, в т. ч. обе версии шумодава (по 155 КБ) | Шумодав кэшировать при первой записи, а не при установке |

## Этап 3. Общий эфир — 1–2 недели

Сейчас v2 честно пишет «другим людям пока не отправляется». Сервер уже есть у v1 (`src/backend.ts`, Supabase) — подключаем к нему.

| # | Что | Как |
| --- | --- | --- |
| 3.1 | **Сжатие записи** | Сейчас запись хранится несжатой: 1,4 МБ на 30 с. Сжимать в AAC (iPhone) или Opus через [Mediabunny](https://github.com/Vanilagy/mediabunny) (WebCodecs) с запасным [AAC-кодировщиком на WASM](https://mediabunny.dev/guide/extensions/aac-encoder) → около 120 КБ на 30 с. Эффекты накладываются до сжатия, как сейчас |
| 3.2 | **Отправка с очередью** | Переиспользовать очередь v1 (`flushQueue` в `src/feed.ts`): запись лежит на телефоне, пока не уйдёт; без сети уходит позже сама |
| 3.3 | **Эфир из сервера вместо демо** | Голоса и ветки — из таблицы `posts`; каналы — по тегам; демо-записи только пока живых мало (как `REAL_ENOUGH` в v1) |
| 3.4 | **Реакции на своих местах — настоящие** | Сейчас чужие реакции на дорожке случайные (`marksFor`), а свои пропадают после перезагрузки. В таблице `reactions` уже есть поле `at` — писать и читать его |
| 3.5 | **Ничего не пропадает** | Запоминать время последнего голоса; при возвращении в приложение и переподключении догружать пропущенное. Подписаться и на реакции в реальном времени |
| 3.6 | **Громкость считается один раз** | Громкость и края тишины считать при публикации и хранить в строке поста — телефоны слушателей не скачивают и не разбирают каждый голос |
| 3.7 | **Защита базы** (новая миграция) | Имя автора — из профиля триггером, не из запроса; запретить менять `audio_path` на чужую папку; `(select auth.uid())` в правилах; индексы на `posts.author_id`, `reactions.user_id`, `reports.user_id`; лимит постов и реакций в минуту; Cloudflare Turnstile для анонимного входа |
| 3.8 | **Помнить, что слушал** | `heard` и `liked` сейчас живут до перезагрузки — хранить на устройстве |

## Безопасность (сделано 13.11.2026, пункт 1 из «что не учтено»)

- «⋯» у чужого голоса в эфире, у голоса в ветке и у каждого чужого ответа: пожаловаться, скрыть, заблокировать автора.
- Причины жалобы — как в v1; «автору может быть нужна помощь» ведёт на экран с тем, что делать при опасности (112).
- Скрытое и заблокированное пропадает из эфира и веток сразу и после перезагрузки; заблокированных можно вернуть в «Моё».
- **Не сделано, нужен сервер:** жалобы копятся на устройстве (`sushhh.v2.reports`) и уйдут модераторам, когда v2 подключится к Supabase (этап 3); очередь модерации и приоритет жалоб «нужна помощь»; блокировка по аккаунту, а не по псевдониму.

## Личные данные (сделано 13.11.2026, пункт 2)

- Перед первой записью — лист согласия: что будет с голосом, правила эфира, подтверждение возраста (16+). Без подтверждения записать нельзя. Согласие хранится с номером версии правил — поменяются правила, спросим снова.
- «Конфиденциальность и правила» — коротко и простыми словами: что хранится, кто слышит, как удалить, правила, возраст.
- В «Моё» → «Мои данные»: удалить все свои записи; удалить все данные (записи, согласие, тема, скрытое и заблокированное, жалобы; язык остаётся).
- **Не сделано:** настоящие юридические документы (политика конфиденциальности, условия использования) — их должен проверить юрист; удаление данных на сервере вместе с аккаунтом (этап 3); проверка возраста сильнее, чем галочка.

## Общий эфир (сделано 13.11.2026, пункт 3 — первая часть)

- v2 на том же сервере, что v1: анонимный вход, псевдоним общий с v1.
- Голоса с сервера встают в эфир (новые сверху), ответы — в ветки, реакции — на свои места на ленте; при ≥5 живых голосах демо убирается.
- Свои записи сжимаются (Opus/WebM или AAC/M4A через Mediabunny; 5 с ≈ 25 КБ) и уходят через очередь: без связи ждут на телефоне.
- Реакции, жалобы (вместе с накопленными без сети), удаление своей записи и «удалить все данные» — и на сервере.
- Новые голоса приходят в реальном времени; при возвращении в приложение эфир догружается целиком — пропущенное не теряется.
- Миграция `supabase/migrations/20261113120000_v2_air.sql`: честный счётчик прослушиваний (одно на человека), имя автора из профиля, запрет «перенаправить» голос на чужой файл, лимиты от спама, индексы, быстрые правила доступа. Применена к базе 13.11.2026.
- **Не сделано:** громкость и края тишины при публикации; догрузка только нового вместо всего эфира; Cloudflare Turnstile для анонимного входа; гости с лимитом.

## Доступ: гости и зарегистрированные (решение 13.11.2026)

Нужен сервер (этап 3), поэтому пока не сделано. Шапка с аватаркой уже есть, аватарка ведёт в «Моё».

| Кто | Что может |
| --- | --- |
| **Гость** (без входа) | Только слушать, ограниченное число голосов в месяц. Счётчик остатка — в профиле под аватаркой |
| **Анонимно под псевдонимом** | Слушать без месячного лимита и реагировать; псевдоним вместо имени, без почты и телефона |
| **Зарегистрированный** | Всё: слушать без ограничений, отвечать голосом, писать свои посты, комментировать |

Что сделать: лимит прослушиваний считать на сервере (по анонимному входу Supabase), а не на устройстве, иначе его обходят перезагрузкой; экран профиля по касанию аватарки — статус, остаток, «войти» и «сменить псевдоним»; закрытые действия (ответить, записать) для гостя ведут на вход, а не прячутся.
